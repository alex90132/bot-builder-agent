# Bot Builder Agent

Telegram-бот с моделью из OpenRouter. Он правит ботов в [конструкторе](https://github.com/fedorabakumets/telegram-bot-builder) и вызывает инструменты других MCP-серверов по URL. Доступ к конструктору берётся из блока, который выдаёт вкладка «Агент».

> Как устроены инструменты конструктора: [обзор MCP](https://github.com/fedorabakumets/telegram-bot-builder/blob/main/docs/mcp/overview.md). Что стоит за этими вызовами: [справочник API](https://github.com/fedorabakumets/telegram-bot-builder/blob/main/docs/api/README.md).

## Что это

Бот принимает задачу текстом и вызывает инструменты подключённых MCP-серверов. Список приходит с сервера (`tools/list`), в код агента он не зашит. Конструктор можно не подключать: тогда работают свои серверы, поиск и картинки.

Через чат можно:

- собрать и поправить сценарий в живой базе, холст обновится сам
- смотреть присланные картинки
- искать в интернете и открывать ссылки
- смотреть проекты, подключать токен BotFather, смотреть статус и логи
- менять срок хранения сообщений: `0`, `7`, `30`, `60`, `90`, `180`, `365`

Поля нод модель не выдумывает: перед новой нодой она смотрит схему. Команды бота только латиницей (`/start`, `/buy`). Тексты сообщений можно писать по-русски.

## Когда использовать

| Из этого чата | В панели конструктора |
|---------------|------------------------|
| Простой бот по описанию | Сложный граф и много медиа |
| Правка сценария словами | Точная раскладка нод на холсте |
| Статус, логи, старт и стоп | Массовая работа с карточками |

## Быстрый старт

Нужны Go 1.26, токен этого бота от BotFather, ключ OpenRouter и уже запущенный конструктор. Картинки заработают, если модель в `AI_MODEL` их принимает. Поиск заработает после раздела «Поиск в интернете».

1. Скопируйте окружение и заполните его.

```bash
cp .env.example .env
```

2. `BOT_BUILDER_URL` нужен только если в чат пришлют голый токен `mcp_…`. По умолчанию это `https://telegram-bot-builder-e3u-production.up.railway.app`. Путь `/mcp` допишется сам.
3. Запустите:

```bash
go run ./cmd/bot-builder-agent
```

4. В конструкторе откройте вкладку «Агент», создайте токен и пришлите боту весь блок `mcpServers`. В нём адрес и заголовок `Authorization: Bearer mcp_…`.
5. Напишите задачу обычным сообщением: какого бота собрать или что изменить.

Проверка без сети и без Telegram: `go test ./...`.

## Поиск в интернете

В комплекте бота SearXNG нет. Его ставят отдельно, один раз, рядом с ботом. Пока он не отвечает, конструктор, меню и картинки работают, а `web_search` и `fetch_url` сообщают, что поиск недоступен.

Нужен Docker. Каталог может лежать где угодно, это не каталог бота.

```bash
mkdir -p searxng/core-config
cd searxng
curl -fsSL \
  -O https://raw.githubusercontent.com/searxng/searxng/master/container/docker-compose.yml \
  -O https://raw.githubusercontent.com/searxng/searxng/master/container/.env.example
cp .env.example .env
```

В `searxng/.env` (это файл SearXNG, не `.env` бота) задайте порт, на котором бот его ждёт по умолчанию:

```bash
SEARXNG_PORT=8890
SEARXNG_BASE_URL=http://localhost:8890/
SEARXNG_LIMITER=false
```

Формат JSON у SearXNG по умолчанию закрыт. Без него бот получит отказ вместо выдачи. До `docker compose up` создайте `core-config/settings.yml`:

```yaml
use_default_settings: true

search:
  formats:
    - html
    - json

server:
  limiter: false
  secret_key: "смените-на-длинную-случайную-строку"
```

Если контейнер уже запускали и в `core-config/settings.yml` лежит чужой файл, допишите `json` в `search.formats` и выставьте `server.limiter: false`.

```bash
docker compose up -d
curl -sS "http://localhost:8890/search?q=test&format=json"
```

В ответе нужен JSON с полем `results`. Пустой список или ошибка движка смотрите так: `docker compose logs -f core`. Остановить: `docker compose down`.

В `.env` бота оставьте `SEARXNG_URL=http://localhost:8890`. Если SearXNG уже стоит на другом порту, второй раз его поднимать не нужно: запишите свой адрес в `SEARXNG_URL`.

SearXNG сам ходит в Google, DuckDuckGo, Yandex и Wikipedia, машине нужен выход в интернет. Этот экземпляр для бота на своей машине: в интернет его лучше не публиковать. Если бот находит ссылки, а страницы не открываются, задайте `WEB_PROXY` (`http://` или `socks5://`). Прокси должен быть доступен процессу бота.

## Окружение

| Переменная | Зачем |
|------------|--------|
| `TELEGRAM_BOT_TOKEN` | Токен этого бота |
| `OPENROUTER_API_KEY` | Ключ OpenRouter |
| `AI_MODEL` | Модель с вызовом инструментов |
| `BOT_BUILDER_URL` | Адрес, если в чат прислали только `mcp_…`. Пусто: публичный хост Railway |
| `TELEGRAM_ALLOWED_IDS` | Telegram id через запятую. Пусто: бот открыт всем, у кого есть свой токен |
| `AGENT_MAX_ROUNDS` | Сколько кругов с инструментами, по умолчанию 16 |
| `AGENT_MAX_RESULT_CHARS` | Обрезка ответа инструмента, по умолчанию 12000 |
| `AGENT_HISTORY_MESSAGES` | Сколько сообщений помнить, по умолчанию 40 |
| `SEARXNG_URL` | Адрес SearXNG для `web_search`, по умолчанию `http://localhost:8890` |
| `WEB_PROXY` | Необязательный прокси для `fetch_url` |
| `DATABASE_URL` | SQLite, по умолчанию `sqlite://data/agent.db` |
| `OAUTH_PUBLIC_URL` | Публичный адрес бота для OAuth. Redirect URI: этот адрес и путь `/oauth/callback` |
| `OAUTH_LISTEN` | Где принимать callback, по умолчанию `127.0.0.1:8787` |
| `MCP_ALLOW_PRIVATE` | `true` пускает MCP на localhost и частные адреса. `false` запрещает |

Блок `mcpServers` в `.env` не кладётся. Список серверов, адреса и секреты хранятся в SQLite отдельно для каждого чата. Файл базы создаётся с правами `0600`.

## Меню

Кнопки внизу и команды делают одно и то же.

| Кнопка | Команда | Что делает |
|--------|---------|------------|
| Задача | обычный текст или картинка | Сообщение и фото уходят модели |
| Проекты | `/projects` | Список, создание, архив, карточка |
| Боты | `/bots` | Токены активного проекта |
| Аккаунт | `/token` | Сохранить блок `mcpServers` или токен `mcp_…` |
| Аккаунт | `/servers` | Список MCP-серверов: добавить, изменить, проверить, включить, выключить, удалить |
| Аккаунт | `/status` | Хост конструктора, маска токена, серверы и последняя ошибка подключения |
| Аккаунт | `/reset` | Очистить диалог, подключения остаются |
| Аккаунт | `/logout` | Забыть токен конструктора и активный проект. Остальные MCP-серверы остаются |
| Отмена | `/cancel` | Выйти из ввода |

`/start` и `/help` показывают это же меню.

На карточке бота: статус, старт, стоп, перезапуск, логи, удаление и срок хранения сообщений.

Пока идёт ответ, в статусе видно только имя инструмента и кнопку «Остановить». Второй текст в этот момент не принимается.

Кнопки удаления, стопа и выхода спрашивают «Да» или «Нет». Такие же вызовы от модели уходят сразу, поле confirm бот добавляет сам.

Картинку из чата бот скачивает и передаёт модели вместе с текстом. В историю байты фото не пишутся.

Поиск идёт через свой SearXNG. Как его поднять и проверить, написано в разделе «Поиск в интернете». Модель вызывает `web_search`, затем `fetch_url`, чтобы прочитать страницу, а не отвечать по короткой выжимке.

## Несколько MCP-серверов

У каждого чата свой список. В записи есть имя, URL, транспорт, способ авторизации и признак «включён». Имя уникально внутри чата. Кнопка «Серверы» и команда `/servers` открывают список. На карточке сервера: проверка, включение, выключение, смена адреса, транспорта и авторизации, удаление, а для OAuth ещё ссылка авторизации.

Старый токен конструктора из базы переносится в сервер `botcraft-builder`. Меню «Проекты» и «Боты» по-прежнему ходит в конструктор этим токеном.

Пришлите целиком блок `mcpServers`. Бот сохранит каждую запись. Серверы, которых в блоке нет, не удаляются. Голый `mcp_…` и блок только с `botcraft-builder` по-прежнему записывают доступ конструктора.

Адрес чужого сервера сохраняется как есть: путь и query не отрезаются, `/mcp` не дописывается. Дописывание `/mcp` остаётся только у конструктора, когда в чат прислали голый токен или запись `botcraft-builder`.

Транспорт выбирается на карточке.

| Транспорт | Что это |
|-----------|---------|
| авто | Сначала Streamable HTTP. Если сервер отвечает как старый HTTP+SSE, бот переключается на него |
| HTTP | Streamable HTTP: без сессии и с сессией, ответ JSON или SSE, заголовок `MCP-Protocol-Version`, `MCP-Session-Id` и закрытие сессии |
| SSE | Устаревший HTTP+SSE |

Локальный stdio не подключён.

Авторизация:

- без авторизации
- Bearer любого вида, префикс `mcp_` не обязателен
- ключ в своём заголовке
- Basic Auth
- несколько своих заголовков
- OAuth 2.1: метаданные ресурса и сервера авторизации, Authorization Code с PKCE, `state`, scopes, resource indicator, обновление токена и повторная ссылка

Заранее зарегистрированный клиент задаётся в карточке строкой `client_id` и, если он есть, секретом. Если прислать `-`, бот регистрирует клиента сам, когда сервер объявляет dynamic client registration. DPoP и mutual TLS бот не делает и пишет об этом отдельной ошибкой.

Для OAuth задайте `OAUTH_PUBLIC_URL`, например `https://bot.example.com`. Redirect URI, который нужно разрешить у клиента: `https://bot.example.com/oauth/callback`. Бот слушает callback на `OAUTH_LISTEN` (по умолчанию `127.0.0.1:8787`). Если публичный адрес смотрит на прокси, прокси должен отдавать этот путь на `OAUTH_LISTEN`. Ссылку бот присылает в чат. После входа в браузере токен пишется в базу, в сообщение он не попадает.

`MCP_ALLOW_PRIVATE=true` (значение по умолчанию) разрешает localhost и частные адреса, чтобы поднять свой MCP рядом с ботом. `false` отклоняет такие URL при добавлении и при подключении.

Инструменты всех включённых серверов уходят модели вместе. Имя для модели: имя сервера, два подчёркивания и исходное имя, например `notes__search`. Так одинаковые имена с разных серверов не сталкиваются и не затирают локальные `web_search` и `fetch_url`. Вызов уходит на тот сервер, которому принадлежит исходное имя. Кэш инструментов и сессия отдельные у каждого чата и сервера. Смена адреса, транспорта или секрета закрывает старую сессию. Сбой одного сервера не отменяет остальные. Если не ответил ни один, модель всё равно может сказать об этом обычным текстом. `tools/call` после неясного обрыва сети сам не повторяется. Обновление просроченного OAuth-токена при ответе 401 выполняется один раз.

Без авторизации:

```json
{
  "mcpServers": {
    "notes": {
      "url": "https://notes.example.com/custom?tenant=acme"
    }
  }
}
```

Bearer:

```json
{
  "mcpServers": {
    "docs": {
      "url": "https://docs.example.com/mcp",
      "headers": {
        "Authorization": "Bearer any-token-here"
      }
    }
  }
}
```

Ключ в своём заголовке:

```json
{
  "mcpServers": {
    "search": {
      "url": "https://search.example.com/mcp",
      "headers": {
        "X-API-Key": "secret"
      }
    }
  }
}
```

OAuth в блоке задаётся адресом. Клиента и ссылку настраивают уже в карточке сервера:

```json
{
  "mcpServers": {
    "calendar": {
      "url": "https://calendar.example.com/mcp"
    }
  }
}
```

Basic Auth и несколько заголовков тоже импортируются из `headers`. В карточке Basic вводится как `логин пароль`, а свои заголовки как JSON-объект. В списке и статусе секреты показаны маской.

## Как бот ходит в конструктор

Запрос меню «Проекты» и «Боты» идёт на адрес конструктора. Заголовок: `Authorization: Bearer mcp_…`, как в выданном конфиге.

Тело: JSON-RPC `initialize`, затем `tools/list` и `tools/call`. Ответ бывает JSON или SSE. После первого `initialize` дальше уходит заголовок `MCP-Protocol-Version`.

Список инструментов кэшируется (по умолчанию 300 секунд). Ошибка `401` значит, что токен не подошёл: его нужно прислать заново.

`load_project` и `save_project` на удалённом `/mcp` сервер не отдаёт. Сценарий пишется инструментами `db_*` и `update_project_db`.

## Ограничения

- Адрес и токен конструктора у каждого чата свои. Голый `mcp_…` идёт на `BOT_BUILDER_URL`, путь `/mcp` дописывается. У остальных серверов URL не меняется.
- Одновременно в чате идёт одна задача.
- В группе бот молчит, пока его не позовут: команда (`/start` или `/start@бот`), упоминание `@бот` или ответ на его сообщение. В личке отвечает на любой текст.
- В лог пишется имя инструмента и id пользователя. Аргументы и сырой `mcp_…` в лог не попадают.
- В исходящие сообщения Telegram токены вырезаются. В истории для модели текст пользователя сохраняется как есть, иначе токен BotFather не дойдёт до `db_add_bot_token`.
